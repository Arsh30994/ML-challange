## Scoring script (validate_submission.py)

- It is a format validator only. It never reads the ground truth and does not compute F0.5 or any other score. The word F0.5 does not appear in it, and it has no singleton scoring logic.
- Rules it enforces: TAB-separated, header exactly `source1_entity_id	matched_entity_ids`, one row per test_source1 S1 ID (none missing, none extra, no duplicate rows), an empty list means no match (singleton), IDs comma-separated with S2-/S3- prefix only, no S1 self-matches, no duplicates within a list, UTF-8.
- Optional `--check-ids` flags IDs that do not exist in test S2/S3. Per its docstring, a nonexistent ID only lowers the score and does not cause rejection.
- Optional candidate_pairs.tsv (header `source1_entity_id	candidate_entity_ids`) gets the same checks, plus a warning (never a failure) when final matches are not a subset of the candidates. The docstring says it is expected in the final zip.
